What is the Problem?

Imagine sending a critical text: "Fire at Sector 4"

  • Messages travel as electrical signals (0s and 1s).
  • The Danger: Bad weather or noise can flip a '0' into a '1'.
  • The receiver gets the wrong message.

How do we know if it was broken?

What is CRC?

CRC stands for Cyclic Redundancy Check.

Think of it like a digital wax seal on an envelope.

  1. The computer uses math to create a unique tag.
  2. If the message is tampered with, the tag breaks!

How Our Project Works

Step 1: The Sender

flowchart TD Data[Emergency Message] --> Bin[Binary: 01101...] Bin --> Math[CRC Math] Math --> Tag[Unique Tag] Bin --> Packet Tag --> Packet[Final Packet Sent]

Step 2: The Network Journey

The packet travels through the internet.

  • Sometimes, electrical noise corrupts the data.
  • We built a button to Simulate an Error.
  • It flips a bit to see if the system catches it!

Step 3: The Receiver

The destination computer gets the packet.

  1. It separates the Data and the Tag.
  2. It does NOT trust the data yet.
  3. It calculates its OWN tag from the received data.

The Final Decision

The Receiver compares the two tags:

✅ YES (They Match) = ACCEPT

The message is perfectly safe.

❌ NO (They Don't Match) = REJECT

The message was corrupted. Stay safe!

Conclusion

CRC-32 is a powerful mathematical tool.

It helps computers catch errors instantly so that we only trust safe data.
